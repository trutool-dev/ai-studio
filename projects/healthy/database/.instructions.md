# Database Agent — Healthy Project

## Fase 1: Infraestructura — Tareas DB-01 a DB-06

Tu misión es preparar la base de datos completamente funcional.
**Carpeta de trabajo:** `projects/healthy/database/`
**No toques otras carpetas.**

---

## Tareas a completar (en este orden)

### DB-01: Ejecutar Prisma migrate dev
- Verifica que `prisma/schema.prisma` existe y está completo
- Ejecuta `prisma migrate dev` en la carpeta raíz del proyecto backend
- Confirma que todas las migraciones aplican sin errores
- Verifica que PostgreSQL está corriendo localmente
- Documenta cualquier error en `database/MIGRATION_LOG.md`

**Éxito:** Schema aplicado sin errores, tablas creadas en PostgreSQL

---

### DB-02: Crear script seed con datos realistas
- Ubicación: `database/seed.ts` (o `.js` si prefieres)
- Debe generar datos realistas:
  - 10 usuarios de prueba con perfiles completos
  - 50 planes de entrenamiento variados (fuerza, cardio, híbrido)
  - 200 alimentos con macros realistas (frutas, proteínas, carbohidratos)
  - 20 ejercicios estándar con instrucciones
  - Historial de sesiones completadas para 3 usuarios
  - Registros de progreso (peso, medidas) distribuidos en 30 días
- Usa datos variados que representen casos reales
- Ejecuta con `npx prisma db seed`

**Éxito:** Base de datos poblada con datos coherentes y realistas

---

### DB-03: Añadir índices en columnas de alto uso
- Archivo: `database/indexes.sql` o directamente en `schema.prisma`
- Indexa las siguientes combinaciones:
  - `user_id` en `Session`, `MealLog`, `ProgressLog`
  - `created_at` DESC en `Session`, `MealLog` (para queries ordenadas)
  - `(user_id, date)` compuesto en `DailyLog` (búsqueda por usuario y fecha)
  - `date` en `ProgressLog` para queries de rango temporal
- Verifica con `EXPLAIN ANALYZE` en PostgreSQL que los índices se usan
- Documenta el impacto en `database/INDEXES.md`

**Éxito:** Índices creados, queries verificadas < 50ms para 10k registros

---

### DB-04: Configurar Redis para caché
- Ubicación: `database/redis-config.md` + script de conexión
- Configura Redis (local o Docker):
  - TTL para planes IA: 24 horas
  - TTL para tokens de refresh: 30 días
  - TTL para sesiones de usuario: 8 horas
  - Estructura de claves: `plan:${user_id}:${date}`, `session:${session_id}`, `user:${user_id}:profile`
- Crea fichero `database/redis.ts` con cliente configurado
- Documenta estrategia de caché en `database/CACHE_STRATEGY.md`

**Éxito:** Redis funcionando, conexión probada, TTLs configurados

---

### DB-05: Verificar integridad referencial
- Audita `schema.prisma`:
  - Verifica que todas las relaciones foreign key existen
  - Confirma que no hay ciclos de dependencia problemáticos
  - Valida que `onDelete` y `onUpdate` están configuradas correctamente
  - Verifica constraints UNIQUE en correo, teléfono, username
  - Confirma NOT NULL en campos críticos (user_id, date, etc.)
- Ejecuta un test de integridad:
  - Intenta insertar registros huérfanos (debe fallar)
  - Intenta actualizar IDs de usuario en sesiones (debe cascada o rechazar según config)
- Documenta hallazgos en `database/INTEGRITY_AUDIT.md`

**Éxito:** Schema auditado, 100% de constraints verificados

---

### DB-06: Documentar ERD actualizado
- Archivo: `database/ERD.md`
- Debe incluir:
  - Diagrama ASCII o URL a Mermaid/Lucidchart embedido
  - Tabla con todas las entidades: nombre, propósito, campos clave
  - Relaciones: parent → child con cardinalidad (1:N, N:N, etc.)
  - Índices principales por tabla
  - TTLs de caché Redis por tipo de dato
  - Notas de performance y decisiones de diseño
- Ejemplo de estructura:
  ```
  User ← (1:N) → Session
  User ← (1:N) → MealLog
  User ← (1:N) → ProgressLog
  Session → (N:1) → TrainingPlan
  MealLog → (N:1) → Food
  TrainingPlan → (N:M) → Exercise
  ```

**Éxito:** ERD completo, legible, útil para otros equipos
